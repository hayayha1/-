# 智能客服知识库 - 知识来源同步（功能规划与业务说明书）

---

## 一、系统功能全景

知识来源同步模块是智能客服知识库的**“自动化数据接入与维护中心”**。
核心目标是：**“让企业原有的文档、网页、内部系统成为知识库的活水源头，一次配置，自动更新，免去人工重复搬运。”**

## 二、六大核心功能模块详解

---

### 功能模块 1：数据源接入管理（连接与配置中心）

该模块用于集中管理所有外部知识源的连接凭据、访问权限和归属关系。

#### 1.1 数据源配置
运营人员可新建一条“同步任务/数据源”，支持填写：
- **数据源类型**：飞书文档、语雀、Confluence、Notion、网页站点、结构化 FAQ 接口、对象存储（OSS/NAS）等。
- **接入凭证**：配置 API 密钥（App ID / App Secret / Token）、账号授权凭证或爬虫 Cookie。
- **业务归属绑定**：明确该数据源同步进来的知识归属于哪一个**产品知识库**（如：绑定到“电商产品库”或“SaaS 核心功能库”）。
- **同步范围白名单**：支持只同步指定的“知识库目录 / 文件夹 / 页面父节点”，避免把无关部门的文档拉入。

#### 1.2 连通性测试（一键体检）
- 在保存配置前，提供**【连通性测试】**按钮。
- 系统自动模拟握手：校验 Token 是否有效、是否有文档读取权限、网络是否可达。
- 若失败，直接给出明确排错提示（例如：“飞书应用未开通 `docx:document:readonly` 权限” 或 “网络超时”）。

#### 1.3 多租户与权限隔离
- 数据源与租户严格绑定：A 企业的飞书授权凭证与目录结构，B 企业绝对不可见。
- 只有具备“知识管理员”或以上角色的账号才可查看密钥、触发同步或修改规则。

---

### 功能模块 2：同步执行策略（自动化调度与变更感知）

该模块控制数据**“什么时候拉取”**以及**“源端变了之后本地如何处理”**。

#### 2.1 三种同步触发模式
1. **全量同步（初始化/全量刷新）**：
   - 首次接入时执行，把外部源指定目录下的所有符合条件的文档整体拉取一遍。
   - 日常运营也可以手动点击“全量刷新”，用于底座重置。
2. **增量同步（日常主力，省资源）**：
   - **定时轮询**：支持配置执行频率（如每 10 分钟、每 1 小时、每天凌晨）。
   - 系统仅比对源端文档的修改时间与内容散列，只拉取有修改或新增的文档。
3. **Webhook 实时同步（秒级响应，体验最佳）**：
   - 支持飞书、语雀等平台的事件订阅。
   - 当员工在飞书里点击“发布/保存”，平台立刻通过 Webhook 通知客服系统，秒级完成局部知识更新。
4. **单次手动同步**：
   - 运营人员在界面随时点击**【立即同步】**，即刻触发一次增量扫描。

#### 2.2 智能变更识别与动作处理
系统通过**“源文档全局唯一 ID”**与本地知识建立强绑定，实现精细化动作：

| 源端发生的变化 | 客服知识库的自动化处理行为 | 解决的业务问题 |
| :--- | :--- | :--- |
| **新增文档** | 自动创建新知识文档，自动切片、建向量索引，生成第一版，即刻上线提供问答服务。 | 零人工介入，新业务文档写完即用。 |
| **修改文档** | 本地自动生成新版本（版本号 +1），刷新检索切片；旧版完整归档在版本历史中，支持随时回滚。 | 业务改了规则（如退换货周期变更），客服系统自动同步更新，且有版本可查。 |
| **删除文档 / 移入回收站** | **默认软删除（失效保护）**：本地文档状态标记为“已停用/失效”，立即从实时问答中剔除，但保留历史版本。也支持配置为彻底硬删除。 | 防止业务上游员工误删飞书文档，导致线上客服问答大面积崩溃。 |
| **移动目录 / 重命名** | 仅更新本地文档归属目录与文档标题，**绝不重复新建文档**，切片与检索索引保持稳定。 | 杜绝传统系统按文件名匹配导致的“移动一下目录就产生重复文档”的乱象。 |

### 功能模块 3：内容解析 & 自动化清洗（数据加工管道）

外部源的内容格式五花八门、夹杂大量杂质，该模块负责将其标准化为干净、适合 AI 检索的高质量知识。

#### 3.1 格式归一化（统一转为标准 Markdown）
- 自动将飞书 Block 块、语雀 Lake 格式、Confluence 复杂 HTML、网页 HTML 统一解析为标准 Markdown。
- 完整保留：多级标题、规范表格、有序/无序列表、代码块、加粗强调等对语义检索至关重要的结构。

#### 3.2 脏数据与噪音剥离
- **网页爬虫降噪**：自动识别并剔除导航栏、侧边栏、页脚版权信息、Cookie 提示、相关推荐等与正文无关的内容。
- **文档降噪**：自动过滤自动生成的目录导航（TOC 块）、点赞统计、正文底部的互动评论区。

#### 3.3 规则过滤与门禁
- **草稿/私密文档跳过**：源端未发布的草稿、带私密权限标签的文档自动忽略，防止内部机密或半成品外流。
- **文件体积保护**：单篇文档超过阈值（如 >10MB）时，自动标记为“超出大小限制”并记录异常，不阻塞整体同步批次。

#### 3.4 图片与外部资源本地化转存
- 飞书、语雀等文档中的内嵌图片通常带有短期防盗链签名，几天后链接就会失效。
- 同步引擎自动抓取内嵌图片，转存至知识库内置的对象存储中，并将链接替换为永久安全链接，确保客服引用溯源时图片永久可见。

#### 3.5 自动切片与向量化上线
- 内容清洗完成后，自动触发系统的分块（Chunking）与向量化计算，无缝入库，无需运营手动点击发布。

### 功能模块 4：冲突防险与人工审查（风控与协同机制）

当外部源和本地客服平台存在双向修改时，该模块提供防踩踏与审查能力。

#### 4.1 变更差异预览（Diff Preview）
- 针对谨慎的企业客户，可开启**“同步预检 / 审批模式”**。
- 同步扫描完成后，界面展示**【变更待确认列表】**：
  - 清晰展示：本次发现新增 X 篇、修改 Y 篇、删除 Z 篇。
  - 点击可查看新旧内容的“双栏文本 Diff 对比”（红绿高亮标出增删改改动）。
  - 运营点击【确认发布】，变更才正式生效并更新向量。

#### 4.2 双端冲突处理策略
当“源端更新”遇到了“运营人员在本地知识库手工修改过的内容”：
1. **源端优先覆盖（默认模式）**：
   - 适用于飞书/语雀是绝对唯一权威源头的场景，本地修改被新版本覆盖，但旧版有备份。
2. **人工介入确认（冲突保护模式）**：
   - 系统检测到两端均有修改，自动挂起该文档的同步，状态标记为“存在冲突”。
   - 线上继续使用当前稳定版本，后台弹窗提醒运营进行“三方对比”，人工选择采用源端版本、保留本地版本或合并。
3. **本地文档锁定（Lock）**：
   - 运营可在本地对重要文档点击“锁定”。锁定后，任何外部同步都会自动跳过该文档，防止自动化流程冲掉关键微调。

---

### 功能模块 5：任务监控、审计流水与异常告警（可观测体系）

提供全透明的运行监控，让管理员对知识同步状态了如指掌。

#### 5.1 同步任务看板
- 列表展示每次同步的历史任务：触发方式（手动/定时/Webhook）、开始时间、耗时、状态（成功/部分成功/失败）。
- 统计数字一眼可见：**扫描总数 / 新增数 / 更新数 / 软删除数 / 失败数**。

#### 5.2 异常明细与下钻排错
- 针对失败文档，单独提供“异常处理列表”，展示具体原因：
  - “文档拉取超时”
  - “飞书 Token 凭证已过期”
  - “文档内容包含不可解析的代码块”
  - “命中源端 API 限流（429）”
- 支持在界面对失败项点击**【重试单篇】**。

#### 5.3 实时通知与告警推送
- 支持配置 Webhook 推送至**企业微信群 / 飞书群 / 钉钉群 / 邮件**。
- **触发场景**：
  - 授权凭据失效（如飞书管理员收回了权限）。
  - 单次同步任务失败率超过阈值（如 >10%）。
  - 同一步任务连续失败 3 次。

---

### 功能模块 6：进阶业务联动（知识挖掘与闭环治理）

将知识来源同步与客服系统现有的**“问答会话、Badcase 纠错池”**深度串联。

#### 6.1 历史人工会话 / 工单高频 Q&A 挖掘
- 对接人工客服的历史聊天记录或工单系统。
- 自动聚类分析客户高频提问、人工客服的标准优质回答，自动生成“候选 FAQ 对”。
- 推送到“知识待审核池”，运营一键点击即可转为正式客服知识。

#### 6.2 跨数据源重复/冲突知识检测
- 当企业同时接入了飞书文档与官网帮助中心时，容易出现两边内容说法不一致或内容重复。
- 系统在同步入库后，自动进行语义重合度检测，提示运营：“本篇文档与《用户服务协议》存在 85% 内容重叠，建议合并或确认权威版本”。

## 三、典型业务场景与操作链路

### 场景 A：日常文档无感同步（最常用）
1. 运营在后台接入“飞书-售后知识库”，设定“每 2 小时增量同步 + 开启 Webhook”。
2. 产品经理在飞书里修改了《7天无理由退换货规则》，点击发布。
3. 飞书秒级向客服系统推送 Webhook。
4. 客服系统自动下载、清洗格式、剔除多余格式、生成新版本、更新切片与向量。
5. 1 分钟后，客户在前端咨询“退换货要几天”，智能客服立刻按照最新规则准确作答。

### 场景 B：外部源文档被误删
1. 某员工在飞书里误将《退款流程指南》移入回收站。
2. 同步任务执行时感知到文档已被删除。
3. 系统**自动将本地文档标记为停用（软下线）**，不参与线上回答，同时企微群发出黄色预警。
4. 运营确认是误删后在飞书还原文档，下一次同步系统自动恢复该文档，历史版本与数据无损保留。

### 场景 C：双端修改产生冲突
1. 客服运营在客服后台临时针对大促把《发货时效》改成了“48小时内”。
2. 仓储部门在飞书源端修改了同一篇文档为“大促期间72小时内”。
3. 同步系统感知到该文档本地被手动修改过，触发**冲突保护**，状态标为“待人工确认”。
4. 线上维持当前有效版本，管理员在后台打开 Diff 对比面板，确认仓储部门口径准确，点击【采纳源端新版本】，完成平稳过渡。

## 四、功能规划落地推荐（三步走）

| 阶段 | 核心实现的功能清单 | 达成的业务价值 |
| :--- | :--- | :--- |
| **第一期 (MVP)** | 1. 接入管理：飞书文档接入（配置凭证 + 连通性测试 + 目录绑定）<br>2. 同步模式：手动立即同步 + 定时轮询增量<br>3. 变更动作：新增入库、修改生成新版本、删除软下线<br>4. 内容清洗：富文本转 Markdown、内嵌图片转存、自动切片发布 | **实现飞书文档自动同步进知识库，替代人工手动复制粘贴**，全链路闭环跑通。 |
| **第二期** | 1. 接入扩展：语雀文档 + 官网帮助中心（网页定向爬虫）<br>2. 实时同步：飞书 Webhook 实时秒级触发<br>3. 协同风控：变更 Diff 差异预览 + 冲突人工确认 + 本地文档锁定<br>4. 监控告警：同步看板流水 + 企微/飞书群异常告警通知 | **实现秒级更新与安全风控**，杜绝误改误删风险，扩展网页主流来源。 |
| **第三期** | 1. 结构化源：FAQ 接口对接与 Excel 批量拉取<br>2. 存储源：企业 OSS / NAS 的 Markdown 监控<br>3. 知识闭环：历史客服会话/工单高频 Q&A 挖掘，打通 Badcase 纠错池 | **实现知识全自动挖掘与全渠道生态互联**。 |
