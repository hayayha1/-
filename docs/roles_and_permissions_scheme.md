基于当前系统已具备的**多租户数据隔离、企业知识库检索编排、文档版本与审核流、外部数据源定时同步、BadCase根因定位与聚类治理、用户画像360°、多渠道客服工作台**等业务能力，对系统的业务逻辑进行全局审视，提出以下**角色与权限重新分配方案**。

---

### 一、 现状痛点与重构动因

当前系统的角色模型较为扁平（超管、技术客服、运营专员、普通客户），在多租户与复杂客服体系落地时存在以下权责边界模糊的问题：
1. **平台运营与企业租户混淆**：平台所有者（SaaS运营商）与单企业租户管理员权限耦合，缺乏“SaaS平台级”与“企业租户级”的分层隔离。
2. **知识管理缺乏“采审分离”**：知识库检索阈值（直接回答/澄清反问）直接影响整套AI准确率，目前缺少知识架构师的专业终审把关。
3. **客服团队缺乏层级梯队**：缺少“客服组长/质检主管”角色，无法对一线坐席的服务质量、满意度差评和人工转接进行巡检与监控。
4. **数据安全与隐私合规**：用户画像中包含手机号、订单历史、负面情绪等隐私数据，一线客服需按单授权查看，而运营人员无需触碰客户敏感身份。

---

### 二、 全新两级六角色体系设计

系统将权限划分为 **“SaaS平台级”** 与 **“企业租户级”** 两个空间，构建清晰的组织架构：

```
SaaS平台层 ─────────────────────────────────────────────────────────────
  👑 平台超级管理员 (Platform Admin) - 负责全平台租户开通、配额、计费与底层大模型管控

企业租户层 ─────────────────────────────────────────────────────────────
  🏢 企业租户管理员 (Tenant Admin)      - 负责本企业坐席配置、品牌白标人设、配额监控
  🧠 知识库架构主管 (Knowledge Master)  - 负责知识审核终审、检索阈值调优、BadCase聚类采纳
  🔍 质检主管 / 客服组长 (QA Supervisor) - 负责全线会话巡检、质检评分、纠纷介入与绩效大盘
  👩‍💼 一线技术客服坐席 (Service Agent)    - 负责接待客户、参考用户画像排错、提报知识草稿
  👤 终端消费者 / 用户 (End User)       - 发起智能咨询、评价反馈、申请转接人工
```

---

### 三、 角色职责与业务定位明细

#### 1. 平台级角色
* **👑 平台超级管理员 (Platform Admin)**
  * **业务定位**：SaaS 平台运营商的主管人员。
  * **核心权责**：
    * 审核并开通新企业租户入驻，设置生命周期（试用/正常/冻结/终止）。
    * 划拨各租户资源配额包（最大知识库数量、坐席席位数、月度 Token 额度、月度问答上限）。
    * 监控全平台多企业资源利用率，处理欠费冻结与扩容服务。
    * 全局底层基础设施治理（大模型厂商接入、通用向量模型配置）。
  * **数据边界**：无权随意查看各企业客户私有会话内容（保护企业隐私），但可监控各租户的调用量大盘。

---

#### 2. 企业租户级角色
* **🏢 企业租户管理员 (Tenant Admin)**
  * **业务定位**：入驻企业的 IT 主管或数字化业务负责人。
  * **核心权责**：
    * **组织与坐席管理**：为本企业创建客服、知识运营人员账号，分配归属产品线及席位。
    * **品牌白标化 (Whitelabel) 定制**：配置企业品牌名、机器人昵称、专属头像、开场权威欢迎语、品牌主色调。
    * **用量与配额健康度监控**：实时查看本月已消耗 Token、已使用问答次数，接收配额不足告警。
    * **知识库全局架构**：新建不同业务线的知识库实例，决定是否开启外部数据源同步功能。
  * **数据边界**：严格隔离在本租户空间内，零穿透至其他企业。

* **🧠 知识库架构主管 / 知识运营专家 (Knowledge Master)**
  * **业务定位**：负责企业知识资产建设、检索召回精度与模型问答质量的核心负责人。
  * **核心权责**：
    * **知识终审与发布**：对一线坐席提交的草稿、外部平台同步拉取的文档进行“发布/驳回”终审，决定何时向量切片入库。
    * **检索参数与置信度调优**：调整直接回答阈值、相似澄清反问阈值、Top-K 重排条数，监控阈值调整审计日志。
    * **外部数据源集成**：配置飞书、语雀等外部文档的增量定时拉取与变更对比。
    * **BadCase 根因闭环治理**：对低置信度、用户差评进行语义聚类分析，决定是否采纳为官方 FAQ、扩充相似问法或修正原文档，并触发回归验证。

* **🔍 质检主管 / 客服组长 (QA Supervisor)**
  * **业务定位**：负责客服团队日常服务质量、VIP 客户纠纷处理与团队效能评估的主管。
  * **核心权责**：
    * **全渠道会话巡视与监听**：查看本企业所有正在进行与已结单的客户会话流，对异常交互进行实时预警。
    * **工单强制调度与协助**：针对疑难问题或“急躁型”客户，可强制改派专属资深客服，或直接介入协助。
    * **坐席服务质检与打标**：对坐席的应答时效、解答准确度进行质检评分；对模型回答偏差一键推送至 BadCase 池。
    * **运营数据看板**：查阅全业务线自助解决率、转人工率、CSAT 满意度大盘与坐席绩效报表。

* **👩‍💼 一线技术客服坐席 (Service Agent)**
  * **业务定位**：直接面对客户、排查技术故障与提供售后保障的一线服务人员。
  * **核心权责**：
    * **多客户会话接待**：接收系统根据产品线自动路由的进线客户，进行实时在线沟通。
    * **360° 用户画像精准赋能**：在对话侧边栏查阅客户详情（VIP 等级、历史订单状态、未结遗留问题、性格标签），按需提供针对性安抚或技术排查。
    * **知识采编草稿提交**：当在服务过程中发现新业务漏洞或知识盲区时，可随时提报 FAQ 或文档草稿（系统自动标记为“待审核”，等待知识主管审批后方可生效）。
    * **会话级差评标记**：在对话过程中对 AI 不当回答进行一键标注（打标错误分类与说明）。

* **👤 终端消费者 / 用户 (End User)**
  * **业务定位**：使用产品服务的外部客户或企业内部员工。
  * **核心权责**：
    * **智能问答交互**：向系统提问，获取 AI 基于权威知识库生成的回答、建议反问或交易查询业务卡片。
    * **服务评价**：对每次 AI 或人工回答进行显式点赞/点踩并输入评价。
    * **诉求升级**：在 AI 无法解决或问题复杂时，点击“转接人工客服”等待专属坐席接管。

### 五、 三大核心业务闭环流转设计

#### 1. 知识沉淀与审核流闭环（采审分离原则）
```
一线客服/外部数据源同步 ──(生成草稿)──► 待审核状态 (PENDING_REVIEW)
                                                │
                                       知识架构主管复核
                                                │
                           ┌────────────────────┴────────────────────┐
                           ▼                                         ▼
                      【审核驳回】                               【审核通过】
                   打回草稿并退回反馈                          切片向量化入库 (ACTIVE)
                                                                     │
                                                              实时服务线上客户
```

#### 2. 服务质检与 BadCase 效果回归闭环
```
客户点踩 / 自动低置信度检测 / 客服标注
                     │
                     ▼
           沉淀至租户 BadCase 待办池
                     │
           质检主管复核并评定服务质量
                     │
           知识主管进行语义聚类分析 (Cluster)
                     │
                     ▼
   【一键采纳】：生成标准问答 / 补充相似问 / 修正文档
                     │
                     ▼
           系统自动发起历史 Case 效果回归验证
```

#### 3. 客户体验与工单流转闭环
```
客户进线提问 ──► AI 知识库精确召回回答 (参考租户品牌人设)
                       │
             遇到复杂问题 / 点击转人工
                       │
                       ▼
         系统调取客户 360° 画像并按产品线路由专属坐席
                       │
                       ▼
           客服专员接管 (结合画像标签与订单详情精准答疑)
                       │
                       ▼
           结单并由客户进行星级评价 ──► 纳入质检绩效大盘
```

---

### 六、 总结与实施建议

1. **去中心化与数据主权**：让平台超管回归“基础设施与商务计量”，把知识运营、坐席人设与质检管理完全归还给企业租户。
2. **知识生产质量受控**：建立“一线客服负责发现问题、知识主管负责权威定稿”的机制，杜绝未经审核的回答直接污染向量数据库。
3. **质检机制保障服务底线**：通过质检主管对用户画像、满意度与会话的定期巡检，确保客诉与负面舆情能被分钟级发现并介入。
